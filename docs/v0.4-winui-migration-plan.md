# v0.4 WinUI App Migration Plan

## Goal

Version 0.4 moves the primary user experience for Device Offboarding Manager to the packaged WinUI 3 app, addressing the signed-script and managed deployment request in Issue #60. Version 0.4.0 is a hard cut: the WinUI app fully replaces the PowerShell module. Version 0.3 is the final PowerShell module release and receives no new features. Critical fixes may be made at maintainer discretion until 0.4.0 ships.

The WinUI app should not depend on launching unsigned PowerShell scripts for its core device search, authentication, offboarding, or reporting flows. That keeps the app viable in tenants that enforce `AllSigned` execution policy through Intune.

## Target Architecture

- `DeviceOffboardingManager.WinUI`: WinUI 3 desktop app using Windows App SDK.
- `Microsoft.Identity.Client`: MSAL.NET authentication for interactive, device-code, certificate, and client-secret flows.
- Graph REST client: authenticated beta Graph calls for Intune, Autopilot, Entra ID, BitLocker, LAPS, and reporting data, with retry and batch support.
- Defender for Endpoint service: REST client for the `WindowsDefenderATP` API, disabled by default and enabled through settings.
- Settings import: managed import path for app registration JSON, replacing the current manual PowerShell config flow.
- PowerShell module: frozen at v0.3 as the final legacy release and superseded by the WinUI app at 0.4.0.

## Deprecation Path

- v0.3 is the final PSGallery module release.
- 0.4.0 is WinUI-only.
- README and PSGallery description will point module users to the app when 0.4.0 ships.

## Distribution Strategy

1. Signed MSIX or EXE GitHub release for early adopters and enterprise validation.
2. Intune Win32/MSIX packaging with documented install command and configuration import.
3. WinGet manifest once signed public installers are stable.
4. Microsoft Store submission after the app passes functional, packaging, privacy, and certification review.

Store publication is valuable, but the first practical milestone should be signed enterprise-ready packages because this is an admin/security operations tool with tenant-specific configuration.

## Milestones

### 0.4.0 - WinUI Application

- Create the WinUI 3 solution and app project.
- Add navigation shell for Dashboard, Devices, Playbooks, Settings, and About.
- Add configuration model and settings import path.
- Add static scaffold validation in CI/local tests.
- Add responsive Fluent layouts, resource-based localization, accessibility metadata, and UI automation coverage.

### 0.4.1 - Authentication and Settings

- Implement MSAL.NET interactive and device-code authentication.
- Implement certificate and client-secret authentication without persisting secrets.
- Import app registration JSON into per-user or managed app settings.
- Show required Graph and Defender permissions in Settings.

### 0.4.2 - Device Search and Dashboard

- Port exact-match device correlation from the PowerShell module into C# services.
- Implement dashboard counts and stale-device summaries.
- Add dashboard distribution, drilldown preview, dashboard CSV export, and device-result handoff.
- Add CSV/TXT bulk import with preview and template export.

### 0.4.3 - Offboarding Workflows

- Port Entra delete/disable, Intune delete/retire/wipe, Autopilot delete/group tag, and Defender offboarding.
- Preserve confirmation dialogs, offboarding summary dialogs, recovery-key warnings, audit logging, and export reports.
- Treat requested-but-missing service targets as explicit failures instead of successful skips.
- Port selected-device Entra group membership lookup.
- Keep Defender optional and permission-gated.

### 0.4.4 - Packaging and Signing

- Add Windows build pipeline for MSIX/EXE artifacts. Delivered for MSIX by `.github/workflows/package-winui.yml`; see `docs/v0.4-packaging.md`.
- Add Authenticode/package signing hooks. Delivered as PFX-based signing with certificate/publisher validation, signature verification, and signed-only tag releases in `.github/workflows/package-winui.yml`; see `docs/v0.4-packaging.md`.
- Add winget manifest generation notes. Delivered in `docs/v0.4-packaging.md`.
- Document Microsoft Store submission checklist. Delivered in `docs/v0.4-packaging.md`.

## Open Decisions

- Package format for the first public artifact: MSIX-only or signed EXE plus MSIX.
- Whether app registration JSON is imported from command-line argument, packaged Intune content, or both.
- Whether future playbooks remain built-in native reports or become a signed/packaged extension model.
- Whether release signing should migrate from GitHub Actions PFX secrets to Azure Trusted Signing.

## Validation

Local static validation:

```powershell
./tests/Verify-WinUIScaffold.ps1
```

Windows build validation:

```powershell
dotnet restore ./src/DeviceOffboardingManager.WinUI/DeviceOffboardingManager.WinUI.csproj
dotnet build ./src/DeviceOffboardingManager.WinUI/DeviceOffboardingManager.WinUI.csproj -c Release -p:Platform=x64
dotnet test ./tests/DeviceOffboardingManager.WinUI.Tests/DeviceOffboardingManager.WinUI.Tests.csproj -c Release -p:Platform=x64
```

Detailed Windows build notes are in `docs/v0.4-windows-build.md`.

# Build the v0.4 WinUI App on Windows

This branch contains the native WinUI 3 / Windows App SDK app track. Build it on Windows 11 with Visual Studio 2022.

## Prerequisites

- Windows 10 1809 or later; Windows 11 recommended.
- A Visual Studio 2022 version that supports the .NET 10 SDK and the selected Windows App SDK.
- Visual Studio workloads:
  - .NET desktop development
  - Desktop development with C++
  - WinUI application development
- Windows App SDK tooling.
- .NET 10 SDK.
- `winapp` CLI for scripted build/run and UI test workflows.

## Restore and Build

From the repository root:

```powershell
./tools/Install-WinUIAnalyzer.ps1
dotnet restore .\src\DeviceOffboardingManager.WinUI\DeviceOffboardingManager.WinUI.csproj
dotnet build .\src\DeviceOffboardingManager.WinUI\DeviceOffboardingManager.WinUI.csproj -c Debug -p:Platform=x64 -p:WinUIAnalyzerPath="$PWD\artifacts\winui-analyzer"
```

The analyzer installer downloads the analyzer from the pinned `microsoft/win-dev-skills` commit and verifies its SHA-256 hash before use.

For Visual Studio:

1. Open `DeviceOffboardingManager.WinUI.sln`.
2. Select `x64`.
3. Build `Debug`.
4. Start `DeviceOffboardingManager.WinUI`.

The project includes `Properties\launchSettings.json` with an `MsixPackage` profile. Visual Studio needs this profile to debug the packaged single-project MSIX app.

If Visual Studio reports that `Properties\launchSettings.json` is missing or does not contain `commandName: MsixPackage`, update to a build that includes that file and reload the project.

The solution enables Deploy for Debug and Release platforms. If Visual Studio says the project must be deployed before debugging, open Configuration Manager and make sure Deploy is checked for `DeviceOffboardingManager.WinUI` on the active platform.

If Visual Studio emits `DEP0840` for `MicrosoftCorporationII.WinAppRuntime.Main` or `MicrosoftCorporationII.WinAppRuntime.Singleton`, continue the debug run first. The Windows App SDK Deployment Manager auto-initializer is enabled so the referenced runtime packages can be registered on first run. If the VM cannot acquire the runtime packages automatically, install the Windows App Runtime from the official Microsoft Windows App SDK downloads page.

## Unsigned Package Build

Use this for validating MSIX packaging shape before adding a signing certificate:

```powershell
msbuild .\DeviceOffboardingManager.WinUI.sln /restore /p:Configuration=Release /p:Platform=x64 /p:AppxPackageSigningEnabled=false
```

## Signed Package Build

For production release packages, use `.github/workflows/package-winui.yml`; it verifies the PFX subject and patches the publisher without committing production identity data. For a local signed test, the manifest publisher must exactly match the certificate subject before building:

```powershell
msbuild .\DeviceOffboardingManager.WinUI.sln /restore /p:Configuration=Release /p:Platform=x64 /p:AppxPackageSigningEnabled=true
```

## Tests

Run the cross-platform scaffold and source checks from any PowerShell environment:

```powershell
./tests/Verify-WinUIScaffold.ps1
```

Run unit tests on Windows x64:

```powershell
dotnet test .\tests\DeviceOffboardingManager.WinUI.Tests\DeviceOffboardingManager.WinUI.Tests.csproj -c Release -p:Platform=x64
```

For UI automation, launch the app, capture its process ID, and run the batch UI suite:

```powershell
./tests/ui-tests.ps1 -AppPid <process-id>
```

The UI suite navigates every page, checks key inputs and automation IDs, captures screenshots, and writes `tests/ui-test-results/test-results.json`. Run it from an interactive Windows desktop; it cannot execute in a headless or non-Windows shell.

## App Configuration

The WinUI app reads and writes settings to:

```text
%LocalAppData%\DeviceOffboardingManager\settings.winui.json
```

The UI supports importing an app registration JSON path. Supported keys include:

- `TenantId`, `tenantId`, or `tenant_id`
- `ClientId`, `AppId`, `appId`, or `client_id`
- `CertificateThumbprint`, `Thumbprint`, or `thumbprint`

Client secrets are not persisted. Enter them only for the current session.

## Current Scope

The WinUI app now contains native C# implementations for:

- MSAL.NET interactive, device-code, certificate, and client-secret authentication.
- Graph REST calls with retry support.
- Page-based WinUI shell with Home, Dashboard, Devices, Offboarding, Playbooks, Settings, and About views.
- Device search and cross-service correlation.
- Native file picker flows for bulk CSV/TXT import with preview/template export and app registration JSON import.
- Dashboard counts, platform filtering, platform/ownership/stale distribution, dashboard-card drilldowns, and dashboard CSV export.
- Autopilot group tag updates and selected-device Entra group membership lookup.
- Entra, Intune, Autopilot, and optional Defender offboarding.
- BitLocker, FileVault, and LAPS recovery-key lookup with sensitive-value audit logging.
- Native report playbooks for Autopilot/Intune gaps, stale devices, ownership, OS posture, recovery-key metadata, and corporate identifiers.
- CSV and HTML report export.
- Localized XAML resources, responsive layouts, keyboard access keys, and stable UI automation identifiers.
- Unit coverage for batch retry/paging, offboarding result semantics, settings secret lifetime, CSV injection defense, and OS support baselines.
- About page changelog rendering, repository launch, and GitHub release update check.
- Branded package icons.

The PowerShell module remains available as the v0.3 compatibility and automation surface.
